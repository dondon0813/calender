# 25 給使用者的操作指南（Opus 指揮 Sonnet 工作流）

這份是給**你（Shirley）**看的，不是給模型看的。目標：用最少的錢，拿到接近高階模型的品質。

## 1. 核心觀念：貴的模型當主管，便宜的模型當員工

- 主對話（你直接聊天的那個）＝**指揮官**：negotiating 需求、拆任務、把關成果。這裡用 **Opus 4.8** 最划算——它訊息量其實不大，貴在「判斷」而判斷正是它的強項。
- 幹粗活（讀一堆檔案、掃程式、批量修改）＝**subagent**：制度已規定指揮官要把這些派給 Sonnet/Haiku 做。粗活燒的 token 最多，讓便宜模型燒。
- 你不需要下任何特殊指令——規則已寫進 CLAUDE.md 和 harness 檔，模型開場就會自動載入照做。

## 2. 每天開工的標準做法

1. 在 Claude Code 把模型切到 **Opus 4.8**（模型選單選 Opus；不確定就問模型「你現在是哪個模型」）。
2. 開場白直接講需求就好，例：「行事曆想加一個 XX 功能」。不用貼任何規則。
3. 想省錢時可以加一句：「**粗活記得派 Sonnet subagent**」——這會提醒它照 20 號守則做。
4. 模型交付時，看它有沒有給你「【需要你操作】」清單（重新部署 GAS、試算表加欄）。照做後回一句「部署好了」，它才能完成線上驗證。

## 3. 目前只用 Sonnet 的話（你現在的常態）

一樣可以直接用，制度對 Sonnet 有加嚴規則（一次只做一件事、更早停下來問你）。但有兩個升級時機，**模型自己會提出**，你只要配合：
- Sonnet 說「這題我連續失敗，建議帶著失敗紀錄換 Opus 4.8 處理」→ 你開個新 session 選 Opus，把它給你的交接訊息貼進去。
- 涉及「要不要多公開一個資料欄位」「大改架構」這類決策 → 建議一開始就用 Opus。

## 4. 什麼時候該開新 session

- 換一個不相關的主題（修 A 功能聊到一半改聊 B 設計）→ 開新的，舊 session 的長對話會拖慢也拖貴。
- 模型開始「忘記前面講過的事」或答非所問 → context 太長了，開新的。重要進度它會存在 memory 和 harness 檔，不會丟。
- 同一件事升級模型時（見 §3）→ 一定開新的。

## 5. 常見錯誤用法對照

| ❌ 常見做法 | ✅ 建議做法 |
|---|---|
| 捨不得用 Opus，複雜任務也全程 Sonnet 硬撐 | 決策和把關給 Opus（訊息少、單價高但總價低），粗活自動派 Sonnet |
| 在同一個 session 裡連做五件不相關的事 | 一件事一個 session |
| 模型說「完成」就直接相信 | 看它有沒有附驗收報告（30 號檔的 D1–D7）；沒有就回「請照 30 號檔驗收」 |
| 自己貼一大段程式碼進對話問問題 | 講檔名和現象就好，讓它自己派 agent 去查（比較省也比較準） |
| 改了 Code.gs 忘記重新部署就測試 | 看到「【需要你操作】」清單先照做，做完回報「部署好了」 |

## 6. 維護這套制度（半年一次就好）

- 對任何模型說：「照 60 號檔檢查 harness 有沒有過時、lessons.md 需不需要精簡」，它會自己跑維護流程。
- 制度檔都在 git 裡，被改壞可以隨時還原（`git log` 找歷史版本）。
