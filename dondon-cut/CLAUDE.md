# dondon cut — 給 Claude 的工作規則

使用者是非工程師，用繁體中文溝通，回報講結論不要講過程。
這是一個本機剪片工具：**你只改剪輯決策，永遠不要碰影片檔本身。**

## 你的工作面

| 你要讀 | 檔案 |
|---|---|
| 講了什麼、什麼時候講的 | `projects/<名字>/transcript.md`（帶時間碼，一行一段） |
| 畫面長怎樣 | `projects/<名字>/frames/00001.jpg`…（每 5 秒一張，可直接 Read） |
| 哪裡在停頓／沒聲音 | `projects/<名字>/silence.json` |
| 目前剪成什麼樣 | `projects/<名字>/project.json` |

| 你只能寫 | 檔案 |
|---|---|
| 剪輯決策 | `projects/<名字>/project.json` 的 `clips` 陣列 |

**禁止**：讀 `audio.wav`、讀原始影片、動 `frames/`、動 `transcript.json`、動 `duration`／`source`／`version`。

## clips 的規則

```jsonc
"clips": [
  { "id": "c1", "in": 12.4, "out": 38.9, "note": "開場自介" },
  { "id": "c2", "in": 95.0, "out": 140.2, "note": "開箱，前面的停頓已切掉" }
]
```

- `in` / `out` 是**原片的秒數**，不是成品的秒數。
- **陣列順序 = 成品播放順序**。要換順序就換陣列位置，不要去改 in/out。
- 同一段素材可以重複出現（想重播就再放一個 clip）。
- `id` 要唯一。新增的用 `c` + 隨機字母數字，不要重複用舊 id。
- `note` 用繁體中文寫**你為什麼這樣剪**——它會顯示在使用者的時間軸上，這是你們溝通的地方。寫了他才知道要不要推翻你。
- 切點前後各留 0.1～0.2 秒，不然聽起來會像被掐住。

## 每次改完必做

```bash
npm run check <專案名字>
```

沒過就修到過，**不要**把有錯的狀態丟給使用者。
存檔後使用者的瀏覽器會自動更新，所以你改的每一版他都會立刻看到 —— 不要把 project.json 當草稿本反覆試。

## 不要做的事

- **不要主動跑 `npm run export`**。那會吃滿 CPU 跑很久，一定要問過使用者。
- **不要大改後才回報**。砍掉超過一半內容之前先說一聲你打算怎麼砍。
- **不要假裝看得到畫面**。你只有每 5 秒一張縮圖。畫面品質、構圖、有沒有手震——講不準就說講不準。
- **不要動 `.gitignore` 讓影片進 git**。

## 常見任務怎麼做

**「幫我剪掉廢話」**
讀 `transcript.md` → 找重複、口誤、「呃」「那個」開頭的段落、明顯的空轉 → 用 `silence.json` 對齊切點 → 重寫 clips。

**「濃縮到 3 分鐘」**
先算現在多長（`npm run check` 會印）→ 按語意重要性排序段落 → 砍到目標長度 → 在 `note` 裡寫你砍了什麼。

**「這段換到前面」**
移動陣列元素，不要改 in/out。

**「把某個主題的部分都留下」**
逐字稿全文掃一次，找出所有相關段落的時間碼，合併相鄰的（間隔 < 1 秒就併起來），輸出成 clips。

## 版本控管

`project.json` 和 `transcript.json` 有進 git，影片和縮圖沒有。
大改之前先 `git diff` 確認目前狀態，改壞了使用者按「復原」或 `git checkout` 都救得回來。
